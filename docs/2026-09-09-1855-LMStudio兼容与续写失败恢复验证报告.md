## 2. 问题与根因

### 2.1 基础连接成功但 JSON 能力检查失败

原探针与 `AIClient.generate_structured()` 均固定传递：

```json
{"response_format": {"type": "json_object"}}
```

实际 LM Studio 返回 HTTP 400：

```text
'response_format.type' must be 'json_schema' or 'text'
```

这表示所选协议不被接受，并不能据此判定模型没有结构化输出能力。
新版上游已改善“推理耗尽 token 导致探针误判”的处理，但仍未覆盖此协议差异。

修复：

1. 新增小型 `JsonCompletion`，探针与业务生成共同使用。
2. 默认保持 `json_object`，不改变既有供应商请求。
3. 仅 HTTP 400/422 且明确要求 `response_format` 使用 `json_schema` 时，切换一次格式。
4. 业务请求使用真实 Pydantic Schema，保留嵌套对象、数组和可选字段；不强行改成会改变字段必填语义的严格 Schema。
5. 格式选择仅在本次逻辑调用内有效，不在不同用户、模型或地址之间共享缓存。
6. 返回内容仍须通过 Pydantic 验证。错误 JSON、字段错误、截断不被视为成功；不降级成无约束文本。
7. 鉴权、网络、上下文超长等问题不会触发协议切换，原有异常脱敏继续生效。

### 2.2 续写无结果却被记录完成，重试报错

原始链路：模型异常 -> generator 发送 error -> 仍发送 `done`（空 ID 列表）
-> API 无条件将请求记为 completed -> 同一请求重试时读取“完成结果” -> 没有结果 ID，抛出异常。

修复：

1. 空字符串和纯空白正文不得写入 Continuation 表。
2. `done` 只代表传输结束；无已保存结果时将请求记为 failed，并保留失败原因。
3. 持久化入口也禁止空结果进入 completed，避免其他调用入口再次遗漏。
4. 多版本请求中，只要有成功版本，继续保留和交付成功结果，不回滚其他版本。
5. 历史 completed 请求只有同时满足 `delivered_count == 0`、`continuation_ids == []` 才允许重新取得执行权。
6. 同一请求的恢复使用状态、交付计数和 claim token 条件更新；其他执行者不能重复取得执行权，旧 token 不能覆盖新任务。空结果在 Python 检查，SQL 不依赖 PostgreSQL 不支持的 JSON 等值比较，也不依赖 SQLite 日期文本精度一致。
7. 有任何交付证据的请求不自动重写；已有成功请求继续走原幂等回放逻辑。

## 3. 测试

### 3.1 先复现，再修复

- JSON 回归：旧代码出现 6 项失败，修复后相关测试组 83 项通过。
- 续写状态回归：旧代码出现 5 项失败，包括异常、空白输出、保存失败与历史空结果回放；补齐恢复边界后相关测试组 53 项通过。
- 新增前端事件测试 2 项，验证失败信息不会被空 `done` 清掉，以及部分成功版本不会丢失。

关键覆盖：

| 场景 | 预期 |
| --- | --- |
| 既有 json_object 供应商 | 请求格式保持不变 |
| LM Studio 明确要求 json_schema | 探针和业务均使用 Schema |
| Schema 返回的字段错误 | Pydantic 拒绝，受限重试 |
| 同一操作解析重试 | 已选 Schema 保留，不反复发送已知不支持的格式 |
| 不同操作/模型 | 不泄漏格式选择 |
| 401/403/503、上下文超长、普通参数错误 | 不冒充格式不兼容 |
| Schema 本身被拒绝 | 无格式循环 |
| 流异常、空正文、保存失败 | 无正文产物，请求失败且可再次尝试 |
| 两版本中一项成功 | 保留成功版本，回放不重复生成 |
| 历史空 completed | 同请求可以安全重新执行 |
| 恢复时第二执行者、旧 token 回写 | 被执行权保护阻止 |
| 历史记录有交付计数或结果 ID | 不自动回收 |

### 3.3 测试是否完备

不能称为完备。项目已有较广的测试基础：本次修复后的源码含 136 个后端测试文件、76 个 Vitest 测试文件，另有 14 个 Playwright spec 文件；CI 有后端、前端及浏览器测试步骤。

但测试数量不等于实际环境全部覆盖。本轮已发现 LM Studio 协议差异与空结果状态缺口。以下仍是明确边界：

- 本轮没有运行全部 Playwright E2E。
- PostgreSQL 的恢复条件做了方言编译断言；完整业务测试在 SQLite 上运行，未冒称做过 PostgreSQL 实库验收。
- `contract` 标记的未实现/延期能力及真实供应商 E2E 不计入默认离线通过数。
- 当天用户使用 Mac mini 生成视频，明确要求延后 LM Studio 实测。因此真实模型 JSON 输出与正文续写尚待验证，不能用 Mock 测试结果代替。
- 尚无针对本次所用本地模型的长篇连贯性、持续生成稳定性或文学质量验收结论。

## 5. 下次真实验证

1. Mac mini 释放内存后启动 LM Studio，确认选定模型已加载并开启可信局域网服务。
2. NovWr 填写 `http://<Mac-mini局域网IP>:1234/v1`；模型名使用服务返回的准确 API Model Identifier。关闭鉴权时可用非敏感占位 Key；启用鉴权时填写实际 token。
3. 先运行“测试连接”，查看 JSON 能力是否验证通过；超时仍需看实际错误，不等同于不支持。
4. 在临时短样本小说中进行世界模型提取，确认真实 Schema 可用；再做一段短正文续写。
5. 再试用户原小说的目标章节，不覆盖已采纳内容。
6. 输入上下文与输出预算必须容纳在已加载模型的上下文窗口内。此前超过窗口的请求不会被本轮 JSON 修复自动缩短，也不会通过静默截掉小说来掩盖。
7. 真实验收通过后记录模型标识、量化、加载上下文、请求参数、实际耗时及返回结果。
